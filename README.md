# Система публикации новостей

Приложение, в котором авторы публикуют новости, а читатели их читают и комментируют.
Сначала это было консольное приложение (ПР1-ПР3), а в ПР5 к нему добавился веб-интерфейс
на Django. Консольная версия при этом никуда не делась и работает как раньше.
Все данные пока лежат в JSON-файлах, так что после перезапуска ничего не теряется.

## Назначение
Приложение представляет собой платформу для создания, публикации и чтения новостных статей. Основная задача — предоставить авторам удобный инструмент для распространения информации, а читателям — доступ к актуальным новостям с возможностью их обсуждения.

## Целевая аудитория
- **Авторы и журналисты:** пользователи, создающие и публикующие новостной контент.
- **Читатели:** широкая аудитория, заинтересованная в получении актуальной информации.
- **Администраторы/Редакторы:** пользователи, модерирующие контент и управляющие категориями.

## Предметная область
Веб-издания, средства массовой информации (СМИ), системы управления контентом (CMS). Область охватывает процессы создания новостей, их категоризации, публикации и взаимодействия с аудиторией через комментарии.

## Основные сущности
- **Автор:** пользователь, создающий и публикующий новости (содержит имя, контактные данные).
- **Новость:** основной контентный объект (содержит заголовок, текст, дату публикации, автора, категорию).
- **Категория:** тематический раздел, к которому относится новость (например, «Технологии», «Спорт», «Политика»).
- **Комментарий:** текстовый отзыв читателя, привязанный к конкретной новости.

## Основные функции
- Создание и публикация новостной статьи автором.
- Присвоение новости определенной категории.
- Добавление комментариев к опубликованным новостям.
- Просмотр ленты новостей с возможностью фильтрации по категориям.

## Что умеет программа
### Веб-версия (ПР5)
В браузере можно:
- посмотреть главную страницу с описанием и цифрами (сколько новостей, авторов, комментариев);
- открыть ленту новостей (свежие сверху) и отфильтровать ее по категории;
- открыть любую новость: текст, автор, дата, просмотры, популярность и комментарии;
- посмотреть список авторов и страницу автора со всеми его новостями.

Пока веб-версия только показывает данные. Добавлять, удалять и комментировать через
браузер научимся позже, когда пройдем формы и POST-запросы. Сейчас это делается в консоли.

### Консольная версия (ПР1-ПР3)
Это консольное меню, в котором можно:
- смотреть ленту новостей и открывать любую новость (при открытии растут просмотры);
- публиковать новости от имени автора - если заголовок или текст пустые, новость не сохранится;
- искать новости по слову из заголовка или текста;
- смотреть новости одной категории и сортировать ленту по просмотрам, дате или названию;
- писать и удалять комментарии (можно анонимно, если не вводить имя);
- удалять новости (комментарии к ним удаляются тоже);
- смотреть, добавлять и искать авторов;
- смотреть статистику: сколько новостей, просмотров, авторов и что самое популярное.

Если ввести что-то не то (буквы вместо числа, несуществующий ID, кривую почту) или файл
с данными пропал/сломался, программа не падает, а пишет, что не так.

## Как проект менялся
- ПР1 - один сценарий: ввел данные одной новости, программа ее вывела.
- ПР2 - новости и комментарии хранились словарями в списках, вся логика была в функциях,
  данные сохранялись в JSON.
- ПР3 - перешел на классы. Новость, автор и комментарий теперь объекты, а функции работают
  со списками объектов.
- ПР5 - добавил веб-интерфейс на Django. Страницы строятся из тех же объектов ПР3:
  view-функции загружают данные через `storage.py` и ищут объекты функциями из `models/`.

## Классы
Все классы лежат в пакете `models`.

### Author - автор
Атрибуты: `id`, `name`, `email`.

Методы:
- `from_data(data)` - `@classmethod`, создает автора из словаря из JSON;
- `is_valid_email(email)` - `@staticmethod`, проверяет почту (пустая тоже подходит);
- `__str__()` - имя и почта в скобках.

### News - новость
Атрибуты: `id`, `title`, `text`, `author` (объект `Author`), `category`, `pub_date`, `views`.

Список категорий - атрибут класса `News.CATEGORIES` (Технологии, Спорт, Политика, Культура),
все остальное попадает в «Разное».

Методы:
- `normalize_category(category)` - `@staticmethod`, приводит категорию к нормальному виду
  (раньше это была функция `assign_category` из ПР1);
- `views` - `@property`, только для чтения. Сами просмотры лежат в `_views`, и поменять их
  можно только через `register_view()`, чтобы никто случайно не выставил ерунду;
- `register_view()` - +1 просмотр;
- `popularity()` - «новая / популярная / вирусная» (бывшая `rate_popularity` из ПР1);
- `matches(query)` - есть ли слово в заголовке или тексте;
- `__str__()` - короткая строка для списка.

### Comment - комментарий
Атрибуты: `id`, `news` (объект `News`), `author_name`, `text`.

Методы: `__str__()` - «Имя: текст» или «Аноним: текст», если имени нет
(раньше этим занималась функция `add_comment` из ПР1).

### Как объекты связаны
```
Comment.news  --->  News.author  --->  Author
```
То есть через комментарий можно сразу добраться до новости и ее автора:
`comment.news.title`, `comment.news.author.name`. Связи хранятся именно объектами, а не id.

Наследование я тут не использовал специально: автор, новость и комментарий - разные вещи,
ни одна из них не «является» другой, поэтому они связаны через атрибуты (композиция).

## Функции
Не все стало методами. Если операция касается одного объекта - это метод. Если она работает
со всем списком (поиск, сортировка, удаление из списка) - осталась обычной функцией в том же
модуле:
- `models/authors.py`: `add_author`, `get_author_by_id`, `find_author`;
- `models/news.py`: `publish_news` (проверка из ПР1), `create_news`, `get_news_by_id`,
  `find_news`, `filter_news_by_category` (генератор), `sort_news` (lambda), `delete_news`,
  `get_statistics`;
- `models/comments.py`: `add_comment`, `get_comments_for_news`, `delete_comment`,
  `delete_comments_for_news`.

Загрузка/сохранение (`storage.py`) и ввод (`utils.py`) тоже остались функциями, потому что
это не поведение новости или автора.

## Веб-часть на Django (ПР5)
Используется Django 5.2, Bootstrap 5.3 (подключен через CDN) и немного своего CSS.

### Django-проект и приложения
- `newsportal/` - пакет настроек проекта: `settings.py` (настройки, список приложений,
  язык `ru-RU`, часовой пояс `Europe/Moscow`), `urls.py` (корневые маршруты), `asgi.py`/`wsgi.py`;
- `manage.py` - команды управления: `runserver`, `check`, `migrate`, `startapp`;
- `homepage` - главная страница, общий каркас страниц `page()` и своя страница 404;
- `news` - лента новостей и страница новости;
- `authors` - список авторов и страница автора.

Комментарии отдельным приложением делать не стал - они показываются на странице новости,
своих страниц у них нет.

Файлы `models.py` в приложениях пока пустые: Django-модели будут в следующих работах.
Не путать с пакетом `models/` из ПР3 - там лежат мои классы `Author`, `News`, `Comment`.

### Страницы и URL
| URL | view-функция | Что показывает |
|---|---|---|
| `/` | `homepage.views.index` | главная: описание, кнопки, цифры |
| `/news/` | `news.views.news_list` | лента новостей, фильтр `?category=Спорт` |
| `/news/<int:news_id>/` | `news.views.news_detail` | новость с автором и комментариями |
| `/authors/` | `authors.views.authors_list` | список авторов |
| `/authors/<int:author_id>/` | `authors.views.author_detail` | автор и его новости |

Маршруты разбиты на два уровня: `newsportal/urls.py` через `include()` отдает адреса,
начинающиеся с `news/` и `authors/`, в `urls.py` нужного приложения. У каждого маршрута есть
имя (`name="news_detail"` и т.д.).

Если новости или автора с таким id нет, страница возвращает свой ответ с кодом 404
("Новость не найдена"). Если адреса вообще нет в маршрутах (например `/abc/`), срабатывает
`handler404` -> `homepage.views.page_not_found`. Свою страницу 404 видно только при
`DEBUG = False`, при `DEBUG = True` Django показывает свою отладочную страницу.

### Как строится страница
`page(title, content)` из `homepage/views.py` собирает весь HTML-документ: `<head>` с кодировкой,
`viewport`, Bootstrap и своими стилями, навигацию и подвал. Каждая view-функция готовит только
свой кусок `content` и вызывает `page()`, так что каркас не дублируется. Текст из данных
перед вставкой в HTML прогоняется через `escape()`.

Bootstrap-классы, которые используются: `navbar`, `container`, `btn`, `card`, `list-group`,
`badge`, `row`/`col`, `display-5`, `lead`, `text-danger`.

## Как хранятся данные
В JSON лежат обычные словари, а связи записаны через id. При загрузке `storage.py` по этим id
находит нужные объекты и связывает их, при сохранении наоборот пишет вместо объекта его id.
Если в файле попалась новость с несуществующим автором (или комментарий к удаленной новости),
такая запись просто пропускается.

`data/authors.json`:
```json
{"id": 1, "name": "Иван Петров", "email": "ivan.petrov@news.ru"}
```

`data/news.json` (`author_id` - ссылка на автора):
```json
{
    "id": 1,
    "title": "Открыт новый технопарк",
    "text": "В городе открылся технопарк для студентов и стартапов.",
    "author_id": 1,
    "category": "Технологии",
    "views": 1250,
    "pub_date": "2026-09-15"
}
```

`data/comments.json` (`news_id` - ссылка на новость, пустой `author` - аноним):
```json
{"id": 1, "news_id": 1, "author": "Максим", "text": "Отличная новость!"}
```

## Как запустить
Нужен Python 3.10 или новее. Ставим Django, pytest и flake8 (лучше в виртуальное окружение):
```
pip install -r requirements.txt
```

### Веб-версия
Один раз перед первым запуском (создаст служебную базу `db.sqlite3`, она в `.gitignore`):
```
python manage.py migrate
```

Проверка настроек и запуск сервера:
```
python manage.py check
python manage.py runserver
```
Дальше открыть в браузере http://127.0.0.1:8000/

### Консольная версия
```
python main.py
```

### Тесты
Сейчас их 42: классы и функции из ПР3, сохранение/загрузка JSON и веб-страницы
(коды ответов 200/404, маршруты, данные на странице, своя страница 404):
```
pytest -v
```

### Проверка стиля кода
Если все хорошо, flake8 ничего не выводит:
```
flake8 .
```
